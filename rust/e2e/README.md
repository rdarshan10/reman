# End-to-end suites (real terminals, real agent SDKs)

These suites drive the **installed** binaries (`~/.reman/bin`) the way a person or an agent would.
The terminal suites run on an isolated daemon (port 8768) against a *copy* of `~/.reman/reman.db`, so your real history is never touched.

| suite | what it drives | needs |
|---|---|---|
| `settings_terminal.py` | `reman settings` in a real terminal, against a sandbox (temp configs, so your setup is untouched). It connects and disconnects a coding tool, shares a suggested and a typed folder, and flips a privacy switch, checking each change on disk | nothing extra |
| `cmd_terminal.py` | a real, plain Command Prompt (no add-ons). It checks that the `r` / `rr` macros load from AutoRun without errors, that the pick is typed onto the prompt and not run, that Enter runs it with quotes, `&`, `|`, `%` and `^` intact, and that Esc clears it | `reman setup` |
| `cmd_clink_terminal.py` | a real Command Prompt with Clink. It checks capture with the real `%ERRORLEVEL%`, that `if errorlevel` still works, text cmd can't quote, the fix suggestion and Alt+F, the finder on ↑ and Ctrl+R, and Tab completion for reman | Clink, plus `reman setup` |
| `powershell_wrappers.py` | exit-code capture when something wraps the prompt after reman: a Python venv's `Activate.ps1` (and `deactivate`), VS Code's shell integration. Also checks that open shells reload reman after an update | the above, plus a venv at `<repo>/.venv` |
| `powershell_terminal.py` | a real interactive Windows PowerShell in ConPTY that loads your profile. It presses the actual keys (UpArrow, Ctrl+R, Tab, Alt+F, Del, F2, Ctrl+T) and reads the screen through a VT emulator | `pip install pywinpty pyte` |
| `powershell_predictions.py` | reman's keys beside PowerShell's own predictions, in a real PowerShell per edit mode and prediction view: Alt+F inserts a fix only while one is waiting and otherwise keeps its own meaning (unbound in Windows mode; ForwardWord in Emacs mode, accepting a word of the inline prediction); with the ListView, Up on typed text moves through the list and on an empty line opens the finder; Tab with nothing to complete accepts the grey prediction, and opens the finder only when there is none; Enter holds a command that keeps failing here once when failing costs something (slow, or it changes things) and never a fast one, offering what worked instead on Alt+F; Alt+N for what comes next; a command with a blank from the finder; `rcd` | `pip install pywinpty pyte` |
| `posix_shells_terminal.py` | bash (Git Bash), zsh and fish (MSYS2) through their `reman init <shell>` integrations. It checks capture, exit codes, suggestions (with what the fix changes), Alt-F (and that it stays forward-word, accepting a word of fish's autosuggestion, when no fix is waiting), Enter holding a slow command that failed every time here and not a fast one (zsh and fish), Alt-N for what comes next, a command with a blank landing the cursor in the blank, `rcd` by folder name, the finder, Tab, and per-command capture cost | the above, plus `pacman -S zsh fish` in MSYS2 |
| `http_agents.py` | the HTTP connector: auth / Origin / boundary checks, REST function calling, the official MCP SDK, and the OpenAI Agents SDK | `reman connect http`; to cover the Agents SDK, run it as `uv run --python 3.12 --with openai-agents --with mcp --with httpx python e2e/http_agents.py` |
| `mcp_stdio.py` | `reman mcp` over stdio with the official MCP client (the path Claude Code, Cursor and others use) | `pip install mcp` |
| `insight_features.py` | the folder insights on a sandbox daemon: what git says changed when a command stops working (another branch, new commits, the same commit, read from a real `.git` on disk), a flaky command called flaky and not broken (and an ordinary fail-fix-pass loop not), what a fix changes (`adds --build`, in the shell's suggestion and `reman_fixes`), an agent retrying a command that fails the same way (the real Claude Code hook tells Claude from the third time, `reman_check` too, `reman agents` lists 4+ retries), typical run time in `reman_check` and search items, time words in search (`terraform yesterday`, `yesterday` alone, agents' `reman_search`), `reman yesterday` by project with fixes and agents, `reman goto` by what ran in a folder or its name (only folders that exist), done alerts for long runs (logged, never shown); the "last time here" line (once per session, never for a folder you were just in, also through fish's `reman-hook welcome`), the "what broke it" note after a command that kept working fails, `reman why`, and the runbook from commands a person ran that worked, including the `reman_runbook` and `reman_check` agent tools; then a repo with three apps on disk: agents' `cd`/`Set-Location`-wrapped and output-filtered commands unwrapped and counted together, each command's folder, variants (and default options) folded, a server's pasted lines and a pasted-together line left out, a piped run's result read from its output (also through the real `reman-hook claude`), the failing step of `a && b`, and a project's declared `pytest` beside a one-file run | nothing extra (uses the build in `target/release`) |
| `ai_runbook.py` | the runbook with a language model, against a FAKE OpenAI-compatible server with scripted answers: the model's summary, order, notes and placements are shown; commands it invents are dropped; secrets never reach it; the per-project cache, `--static`, `--refresh`, the fallback on a useless answer, agents getting the fuller runbook in the background, and `"enabled": false` | nothing extra |
| `privacy_agents.py` | privacy at capture (secrets masked and never in the database file, unlocatable ones not stored, `"secrets": "drop"`, `ignore_commands` / `ignore_folders` picked up live), `reman scrub` on history stored before, Claude Code durations and error text, Codex capture with an unknown outcome, `reman connect codex` writing and `disconnect` removing its hooks.json, and fixes offered for a different command that failed with the same error; and what an agent is told: its own project visible though unshared, other unshared folders not (with a note saying why), commands that only failed counted when left out, and an empty search saying so | nothing extra (uses the build in `target/release`; the connector checks write into a sandboxed home) |
| `finder_terminal.py` | the finder opened from a real PowerShell prompt, against a sandbox daemon and config: inline under the prompt (output above untouched, the prompt where it was, nothing left after Esc), scrolling the screen up when the prompt is at the bottom with the pick landing on the moved prompt and PSReadLine drawing in the right place after; your own commands first and F3 through yours and agents', agents' only; Ctrl+O listing every run with when, how long, who and the exit code, Del Del forgetting one run; vim keys (normal mode shown, j k, i, q); and the whole-screen setting | `pip install pywinpty pyte` |
| `output_capture.py` | `reman shell` running PowerShell in ConPTY inside the test's own ConPTY, against a sandbox daemon: the shell knows it's inside, no marks reach the screen, each command's output kept with its run (no echo, colours gone, a progress line as it ended, 300 lines whole, secrets masked), a native program's output and exit code, `reman output` by command, by what it printed and `--failed`, Ctrl+O showing a run's output, a resize reaching the shell, `exit 5` leaving with 5, the setting that opens every shell inside it (on and off); agents' output from their hooks, `reman_output` only inside shared folders, and `output_runs` limits | `pip install pywinpty pyte` |
| `nu_xonsh_terminal.py` | nushell and xonsh with `reman init nu` / `reman init xonsh`, each in a real terminal: capture through the spool and reman-hook with exit codes and folders, the fix after a typo and Alt+F, Up and Ctrl+R opening the finder and Enter placing the pick, Alt+N, `rcd`, reman's own keys never recorded as commands; then each inside `reman shell`, its output kept | nushell and xonsh, found as `REMAN_NU` / `REMAN_XONSH` or on PATH (one that's missing is skipped) |
| `keys_terminal.py` | the user's own keys (`keys` in config.json) in real PowerShell, bash, zsh and fish, against a sandbox daemon and config: with ↑ and Tab given back, ↑ is the shell's own again and Alt+J opens the finder, Alt+K inserts the fix, in the finder Ctrl+E is "every run" (Ctrl+O no longer) with the hint line saying so, and a change made while PowerShell is open applies at its next prompt | MSYS2's zsh and fish, as for `posix_shells_terminal.py` |
| `tui_resize.py` | the finder and `reman settings` at many window sizes in ConPTY, against a sandbox daemon and config: the layout at each size (hints, query and tabs, card beside or above the list, a whole "too small" note), and after resizing while open (grow, shrink, wide to narrow, too small and back, with the help overlay, a long query, a long folder path) the screen matches a fresh launch at that size | `pip install pywinpty pyte` |
| `uninstall_sandbox.py` | `reman uninstall` in a sandbox (fake ~/.reman, sandboxed home and profile; the registry and PATH are skipped): nothing without confirmation, `--dry-run` lists and changes nothing, `--yes` removes reman from Claude Code and Codex, the HTTP endpoint, the profile block and the rc line while keeping the user's lines, deletes the program folder once it exits and keeps the history; `--purge` deletes that too | nothing extra (uses the build in `target/release`) |
| `search_quality.py` | search by meaning, on its own sandbox history (everyday commands plus 250 agent-style scripts): a described command must rank first and be marked close; a never-run intent must get nothing marked close; a query naming a tool you use (`astro`, `vercel`) must get nothing close from another tool. The website's examples come from here. `--real-db` also checks a copy of your own history; `--dump` writes the evidence the close rule in `search.rs` was calibrated on | nothing extra (uses the build in `target/release`) |

To run a suite: `python e2e/<suite>.py`. Each prints `ok` or `FAIL` per check and a final `RESULT`.

The suites that drive the installed binaries can test another build instead: set `REMAN_EXE_UNDER_TEST` to its `reman.exe` (and `REMAN_BIN_UNDER_TEST` to its folder, for `posix_shells_terminal.py`).
